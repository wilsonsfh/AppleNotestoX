X bookmarks → wiki: 3 ways (pick one to start)

Endpoint is GET /2/users/{id}/bookmarks (OAuth2 user-context, scopes bookmark.read tweet.read users.read). An “X MCP” just wraps this — it does not avoid the App + auth + paid tier.

MVP · recommended first

Paste / share a tweet URL

  • You paste one or more x.com links; app fetches public oEmbed/syndication text + author.
  • Writes raw/articles/<date>-x-<handle>.md with provenance.
  • No API key, no cost, no OAuth. Manual, not bulk.
Full · later

Official bookmarks sync

  • Create an X developer App, OAuth2 PKCE login once, store refresh token in Keychain.
  • Pull all bookmarks (paginated) → raw/, dedupe on tweet id.
  • Needs a paid X tier (Basic+) and token refresh. Bulk + repeatable.
Avoid

Scrape / session cookies

  • Drive a logged-in browser session to read the bookmarks page.
  • Brittle, breaks often, and against X ToS.
  • Only mentioned so we can explicitly rule it out.

This is ~5 features — suggested build order

Each is its own small spec → plan → implement. Ordered by value-per-effort and dependencies, so you get wins fast and the risky/paid piece is last.

  1. Study core — “↻ Refresh study data” (runs generate.mjs) + “◎ Launch Wiki Review” + live counts. Smallest, highest daily value; all local. Fixes the “stale data” problem permanently.
  2. Synthesis backlog — compute & list raw/ items with no wiki/sources/ page; “Copy opencode prompt”. Local; turns the invisible into a to-do list (12 today).
  3. Wiki Studio shell — reframe the window into the 3-stage hub; demote Notion to a capture source. Moderate SwiftUI; wraps #1–2.
  4. Capture menu — unify existing importers (Apple Notes export, Video, Notion) behind “＋ Capture”. Mostly wiring what already exists.
  5. X bookmarks — ship the paste-URL MVP first; gate full OAuth sync on whether you’ll pay for an X tier. Largest, external, optional cost.

Before I write the spec — a few decisions

  1. Scope to start: ship #1+#2 first (study + backlog, ~1 focused pass), or do the full Wiki-Studio reframe (#1–#4) in one go?
  2. X path: start with the no-cost paste-URL MVP, or do you already have (or will pay for) an X developer tier so we build the real bookmarks sync?
  3. Notion: keep it as a capture source, or drop it from the GUI entirely (it stays a CLI tool)?
  4. “Synthesize” button behaviour: the app can’t safely write wiki/ itself (that’s LLM-owned). OK if it just surfaces the backlog + copies an opencode prompt for you to run? Or do you want it to shell out to opencode directly?
  5. “Synthesized?” signal: is “a wiki/sources/<same-name>.md exists” good enough, or should it also grep the wiki for references / a frontmatter flag (more accurate, more work)?
